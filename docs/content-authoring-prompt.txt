아래 TOPIC 하나에 대해 caniignoreit.com에 바로 넣을 수 있는 완성 콘텐츠를 작성해줘.

TOPIC:
[여기에 토픽 하나만 적는다]
════════════════════════════════════════════════════════════════════════

■ 한 번에 TOPIC 하나만 출력한다.
  여러 토픽을 한 응답에 이어 붙이면 importer가 전부 하나의 문서로 읽어서
  SLUG이 덮어써지고 SCENARIOS가 한 배열에 뒤섞인다. 반드시 하나씩.

목적:
나는 네 출력물을 수정하거나 재가공하지 않고 그대로 repository importer에 넣는다.
따라서 설명, 서론, 후기, 코드블록, 형식 밖의 코멘트 없이 오직 최종 콘텐츠만 출력해야 한다.

반드시 최신 웹 검색을 충분히 수행해서 사실관계를 검증한 뒤 작성한다.
가능하면 정부기관, 규제기관, 제조사, 표준기관, 학술기관 등 1차 출처를 우선 사용한다.
출처가 뒷받침하지 않는 수치, 기간, 거리, 고장 진행 속도, 위험 확률을 임의로 만들지 않는다.

현재 caniignoreit.com의 기존 페이지를 직접 열어보고 그 수준과 문체를 기준으로 삼는다.
(이 지시는 매우 중요하다.) 예: https://caniignoreit.com/browse/

1-4. RELATED의 slug과 ACTIONS의 destination_problem_slug는
     1-2와 1-3의 목록에 있는 것만 쓴다.
     목록에 없는 slug을 지어내면 import가 실패한다.
     적당한 것이 3개가 안 되면 적게 넣는다. 하나도 없으면 RELATED를 생략해도 된다.
     숫자를 채우려고 관련 없는 페이지를 연결하지 않는다.


1-5. 글자 수 상한 (초과하면 import 실패)

  SEO_TITLE 75          META_DESCRIPTION 170     REVIEW_SCOPE 200
  NAME 160              EYEBROW 120              H1 200
  CAN_I_USE_IT_QUESTION 120                      CAN_I_USE_IT_LABEL 120
  scenario   label 200 / short_description 300 / result_headline 160 / recommended_action 300
  consequence stage_label 120 / title 200 / chain_label 80
  window     situation 200 / ignore_answer 80 / what_to_do 300
  action     title 200 / destination_label 200
  flag       title 200 / description 400
  faq        q 300
  source     publisher 200 / title 300 / notes 400
  resource   title 200 / description 500
  related    anchor_text 11자 이상 200자 이하

  상한이 없는 필드: SHORT_ANSWER, WHY_IT_MATTERS, scenario result_body,
  action body, faq a, DISCLAIMER. 여기서는 자연스러운 길이로 쓴다.


1-6. 숫자 + 시간/거리 단위 표기 금지 (정규식으로 차단된다)

  다음 필드 안에서 "2 hours", "30 minutes", "50 miles", "10 km" 형태를 쓰지 않는다.
    SHORT_ANSWER / WHY_IT_MATTERS / scenario result_body / scenario recommended_action
    window what_to_do / action body / faq a

  출처가 뒷받침해도 차단된다. 필요하면 영어 단어로 쓴다: "two hours", "one hour".
  허용되는 것: 온도(40°F), 퍼센트, 연 단위(10 years), 초 단위(30 seconds),
  면적(10 square feet).


1-7. SOURCES

  source_type이 government 또는 regulation인 항목이 최소 하나 반드시 있어야 한다.
  없으면 import가 실패한다.
  url은 실제로 확인한 https 주소이거나 null. 추측한 URL 금지. example.com 계열 금지.
  같은 기관의 사실상 동일한 페이지를 숫자 채우기용으로 반복하지 않는다.
  notes에는 그 source가 실제로 말하는 범위까지만 적는다.


1-8. RESOURCES에는 url과 affiliate를 넣지 않는다. (넣으면 실패)


1-9. REVIEW_SCOPE에 "reviewed by", "technician", "ASE-certified", "Dr." 를 쓰지 않는다.
     검토자 자격을 주장하는 표현이 금지되어 있다. 200자 이내 한 문장이면 충분하다.


1-10. 출력에 markdown을 쓰지 않는다.
      **굵게**, `코드`, # 제목, 표, 코드펜스 모두 금지.
      값 안에 쓴 글자는 그대로 웹사이트에 나간다.


────────────────────────────────────────────────────────────────────────
2. 품질 기준
────────────────────────────────────────────────────────────────────────

2-1. 사용자가 이 페이지 하나만 읽어도 다음을 바로 이해할 수 있어야 한다.
   · 지금 무시해도 되는지
   · 얼마나 급한지
   · 어떤 상황이면 판단이 달라지는지
   · 지금 무엇을 해야 하는지

2-2. 영어는 실제 미국 소비자용 정보 사이트처럼 자연스럽고 직접적으로 쓴다.

  금지:
   · 같은 말을 여러 section에서 문장만 바꿔 반복
   · 과도한 hedge
   · 쓸데없는 비교와 대조
   · 결론을 늦게 말하는 방식
   · AI 특유의 지나치게 정돈된 문장
   · 추상명사 남용
   · 불필요한 서론
   · 독자를 훈계하는 표현
   · dramatic하거나 공포를 과장하는 표현

2-3. 판단은 충분히 단호하게 하되 근거보다 강하게 말하지 않는다.

  특히 금지:
   · 특정 제조사 guidance를 모든 제품에 일반화
   · 특정 recall이나 특정 사건을 전체 제품군에 일반화
   · 특정 차량 TSB를 모든 차량에 일반화
   · 특정 지역 법규를 미국 전체 법처럼 표현
   · "EPA says", "CPSC says", "USDA says", "Federal law requires" 라고 써 놓고
     실제 source가 그 문장 전체를 지원하지 않는 경우
   · source에 없는 "within days", "after several weeks", "over a season" 같은
     임의의 진행 시간

  시간 흐름이 필요하면 조건형으로 쓴다:
   "If the problem continues" / "After repeated exposure" / "If corrosion develops"

2-4. 안전 관련 문장은 자연스럽게 만들겠다고 위험 수준을 약화하지 않는다.
     화재, 감전, 중독, 브레이크 고장, 구조물 붕괴, 배터리 발화 등은
     실제 근거가 있다면 명확하게 유지한다.

2-5. 미국 독자를 기본 대상으로 한다.
     다만 법, 보험, 임대인 책임, 검사제도처럼 주/지역에 따라 달라지는 내용은
     전국 공통 규칙처럼 단정하지 않는다.

────────────────────────────────────────────────────────────────────────
4. 출력 전 자체검수
────────────────────────────────────────────────────────────────────────

· SYSTEM / CANONICAL_PATH / EYEBROW가 1-1 목록의 같은 줄에서 나왔는가
· CANONICAL_PATH의 마지막 조각이 SLUG과 정확히 같은가
· SLUG이 1-2(이미 발행됨) 목록에 있지 않은가
· RELATED와 destination_problem_slug이 전부 1-2 / 1-3 목록 안에 있는가
· government 또는 regulation source가 하나 이상 있는가
· 1-5의 글자 수 상한을 넘긴 필드가 없는가 (특히 SEO_TITLE, META_DESCRIPTION, REVIEW_SCOPE, ignore_answer)
· 1-6의 숫자+시간/거리 표기를 쓰지 않았는가
· RESOURCES에 url을 넣지 않았는가
· verdict가 본문과 일치하는가
· urgency / safety risk가 scenario들과 충돌하지 않는가
· 동일 사실을 여러 section에서 쓸데없이 반복하지 않았는가
· 출처보다 강한 주장을 하지 않았는가
· source URL이 실제 확인된 주소인가
· manufacturer-specific 내용을 일반화하지 않았는가
· 법/보험/임대 책임을 미국 전체에 일반화하지 않았는가
· 서로 모순되는 문장이 없는가
· 안전 관련 행동이 오히려 사용자를 위험하게 만들지 않는가
· FAQ가 본문의 복사본처럼 되어 있지 않은가
· markdown을 쓰지 않았는가

문제가 있으면 출력 전에 스스로 수정한다.

최종 응답에는 위 3번 양식으로 작성된 콘텐츠만 출력한다.
설명, 분석, 평가, markdown code fence는 붙이지 않는다.
