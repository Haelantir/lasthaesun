그리고 저는 이 구조를 Can I Ignore It 전체의 고정 규칙으로 잡는 게 좋다고 봐요.

DOMAIN → OBJECT → SYSTEM → PROBLEM

예를 들어:

Mobility → Cars → Tires → Low Tire Pressure

Home → Plumbing → Drains → Slow Drain

Appliances → Coffee Machines → Maintenance → Descaling

Tech → Windows → Updates → Security Update

이렇게요.

이렇게 설계하면 나중에 500페이지가 아니라 50,000페이지가 생겨도 사이트가 안 무너집니다. 이게 지금 미리 상위 분류를 하나 넣어두는 가장 큰 이유입니다.
